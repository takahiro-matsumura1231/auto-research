# Linear の運用ルール

Linear は「今なにをしていて、何が残っているか」を見るための場所。研究上の判断と証拠はリポジトリ（判断ログ・台帳・結果文書）に残し、Linear にはそこへのリンクと状態を置く。チームキーとプロジェクト名は [`project.yaml`](../project.yaml) の `linear` にある。

## 単位

- **1つの実験・1つの執筆項目・1つの事務作業 = Issue 1件。**
- 大きな実験（段階A・Bなど）は親Issueに子Issueをぶら下げる。親の完了条件は「子Issueがすべて完了」。
- ラウンドの台帳の行と Issue は1対1にする。台帳の「完了条件・証拠」列に Issue 番号を書く。

## ラベル

| ラベル | 使う場面 |
|---|---|
| `Experiment` | 学習・評価・解析・監査 |
| `Writing` | 論文本文、図表、回答書、提出物 |
| `Admin` | 確認・連絡・記録、データの受け取り |
| `Bug` | 実装・データの不具合 |

## 状態と台帳の対応

| Linear | 台帳の状態 |
|---|---|
| Backlog | 候補 |
| Todo | 未着手 |
| In Progress | 調査中 / 設計中 / 登録済 / 実行中 / 分析中 |
| In Review | 結果文書・プロトコルのレビュー待ち、ユーザーの確認待ち |
| Done | 完了 |
| Canceled | 中止（理由を progress と判断ログに書いてから） |

`保留` は Backlog に戻し、コメントで理由と再開条件を書く。

## Issue の書き方

```markdown
## 背景・目的
なぜこの作業をするか。前の結果や指摘へのリンク。何を切り分けたいか。

## 方針
- 何を変え、何を変えないか
- 選択は内側の分割だけで行う／評価データは採点時に一度だけ使う
- 比較の単位と区間の計算方法

## 完了条件
- 採点前登録が済み、判断ログ NNNN に記録されている
- 全採点単位の予測・manifest・再読込可能な checkpoint が保存されている
- 結果文書が数値照合を通っている

## Source
- docs/rounds/<round>/README.md の行 ID
- docs/protocols/<id>_protocol.md
- 関連する過去の判断ログ

## 決定（YYYY-MM-DD）
途中でユーザーや指導教員が決めたことを日付付きで追記する。
```

## いつ何を更新するか

| タイミング | Linear | リポジトリ |
|---|---|---|
| 作業を思いついた | Issue作成（Backlog） | 台帳に `候補` の行 |
| 着手 | In Progress | 台帳を `調査中`、progress に開始を追記 |
| 採点前登録 | コメントに登録文書・ハッシュ・判断ログ番号 | プロトコル、設定、判断ログ |
| 実行開始 | コメントに予算・PID・ログの場所 | progress |
| 結果 | コメントに主要結果の1行と結果文書のリンク | 結果文書、progress |
| 完了・中止 | Done / Canceled | 台帳、progress、必要なら判断ログ |
| ユーザーの決定 | 説明欄の「決定」に追記 | 判断ログ |

## コミットとの結び付け

コミットメッセージの先頭か括弧に Issue 番号を書く。

```
ABC-12: Register feature-ablation protocol (decision 0031) and its runner
Draft feature-ablation protocol (ABC-12, not yet registered)
```

## エージェントへの権限

- Issue の作成、コメント、状態変更は、エージェントが行ってよい。
- Issue の削除、他人が担当する Issue の変更、プロジェクトやラベルの作成は、ユーザーに確認する。
- Linear に機密データ（認証トークン入りのURL、個人情報、未公開データの中身）を書かない。
