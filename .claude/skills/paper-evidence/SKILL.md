# /paper-evidence

## 原則

- 保存済みの予測・checkpoint・manifest・プロトコル・計算法にたどれない値は、確定値として使わない。
- 内部評価（開発データ）と独立テスト（全ての選択の後に初めて使ったデータ）を分けて書く。
- 内部ラベル（実験ID、Issue番号、判断ログ番号）を本文・図表に出さない。
- 遡及的な比較を独立した性能と書かない。区間が0を含む差を「優れる」と書かない。

## 手順

1. `docs/paper/paper_brief.md` を読み、未確定の項目があればユーザーに確認する（投稿先、形式、主張）。投稿規定は要約して brief からリンクする。
2. 原稿の主張・数値・図表ごとに、`docs/paper/evidence_index.md` に1行作る: 根拠、使う図表、採用値、生成コードと manifest、使う前の確認、確認日。
3. 各図表を `tools/paper_<name>.py` で生成する。出力は `results/paper/<name>/` に、値は `values.json` と manifest（入力ファイルの SHA-256）に保存する。手で数値を入力しない。
4. 原稿中の数値に照合注釈を付け、`tools/verify_doc_numbers.py` で照合する（LaTeX なら `% verify:` コメントも使える）。
5. 指導教員やユーザーの判断（例: どのテスト集合を独立テストと呼ぶか）は brief の「決定の記録」と判断ログに書く。古い記述と食い違う場合は、新しい判断が優先することを台帳に明記する。
6. 区切りごとに Linear の `Writing` Issue を更新する。
