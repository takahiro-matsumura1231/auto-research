# /new-round

## 1. 聞くこと（不明なものだけ）

- ラウンドの短い名前（ディレクトリ名、例: `round2`, `paper`）と目的を1文で
- きっかけ（受けた質問・指摘、前のラウンドの結論）
- 期限と予算（GPU時間）
- 既に決まっている境界（例: 「論文化では新しい比較学習をしない」）

## 2. 現状を読む

- `project.yaml`、`docs/handover.md`、判断ログの最新項目、前のラウンドの台帳と progress の末尾
- 前のラウンドで `保留` や `候補` のまま残った項目を拾う

## 3. 雛形から作る

`docs/rounds/_template/` の4ファイルを `docs/rounds/<round>/` にコピーして埋める。

- `README.md`: 目的、状態、使い方、台帳。台帳の最初の行は原則として「ベースラインと評価資産の固定」「誤差・失敗例の監査」「仮説と優先順位の確定」。ID の接頭辞は `R<n>-`。
- `context.md`: 受けた質問を1行ずつ。保存済みの証拠で答えられるものは根拠リンク付きで答え、答えられないものは「未検証」にする。
- `plan.md`: 検討の順番、各段階の終える条件、予算。「全部やる約束ではない」と書く。
- `progress.md`: 開始の項目（背景・確認済み・未解決・方針・次）。

名前が既存の「Phase」「版」と衝突する場合は、別の管理単位だと README に書く。

## 4. Linear

`project.yaml` の `linear.team_key` / `linear.project` を使う（docs/linear.md の書式）。

- 親Issue「<ラウンド名>: <目的>」を作る。
- 台帳の各行に子Issueを作り（最初の行は Todo、他は Backlog）、台帳の「完了条件・証拠」列に番号を書く。

## 5. 記録

- `docs/README.md` の表と `docs/handover.md` の「進行中のラウンド」を更新する。
- `/record-decision` で「<ラウンド名>を開設」を判断ログに追記する（境界と予算を「約束すること」に書く）。
- コミット: `Open <round>: ledger, plan, context (ABC-NN)`

最後に、ユーザーに台帳の表と次の一手（R?-00 の内容）を示す。
